\section{Supplementary material}
\label{sec:appendix}

\paragraph{S1. Full benchmark grid.} The full comparison table contains $648$ completed cells
($6$ datasets $\times$ $4$ rare-label budgets $\times$ $3$ seeds $\times$ $9$ methods) with rare-cell F1, recall,
precision, FFR and run status. All cells are marked successful in
\path{results/comparison/comparison_summary.csv}; aggregate scarce-regime summaries are in
\path{results/comparison/comparison_summary_agg.csv}.

\paragraph{S2. Paired significance tests.} The paired scarce-regime comparison uses cells indexed by dataset,
rare-label fraction and seed ($n=54$). Against scANVI, scRareRefine has $29/25/0$ wins/ties/losses with mean
$\Delta$F1 $=+0.160$ and bootstrap $95\%$ CI $[+0.085,+0.244]$; all baseline contrasts have confidence intervals
excluding zero. The full table is stored in \path{results/comparison/significance_test.csv}.

\paragraph{S3. Distinct labelled configurations.} The rare-label budget is floored at five cells, so several nominal
fractions map to the same labelled set on small rare populations. The $18$ nominal scarce cells collapse to $15$
distinct labelled configurations; scRareRefine is win-most in $15/15$ and single-best in $14/15$. The accounting is
stored in \path{results/comparison/scarce_region_distinct.csv}.

\paragraph{S4. Separability sensitivity.} Benchmark-wide sweeps over
\(\sep_{\mathrm{low}}\in\{0,0.7,1.0,1.3,1.6\}\) show that $1.3$ is the smallest evaluated threshold with no FFR
violations on the real benchmark. Lower thresholds raise mean F1 but admit two Baron-pancreas FFR violations; raising
the threshold to $1.6$ sacrifices F1 without improving worst-case FFR. The table is
\path{results/sep_sweep/lowsep_sensitivity_agg.csv}.

\paragraph{S5. Recall recovery panel.} \Cref{fig:supp-recall} reports the supporting rare-cell recall curves derived
from the multiseed aggregate table. The pattern mirrors the main F1 curves: recall recovery is largest where the
backbone under-recovers the rare class and is minimal when the backbone is already saturated.

\paragraph{S6. Weak-backbone rescue.} The weak-backbone demonstration (\cref{tab:weak-backbone}) supports the
mechanistic claim that the rescue procedure can improve a weaker base predictor in aggregate. It also shows why we
do not claim backbone-agnostic no-regression: there is one negative scarce cell and two negative cells overall. The
source files are \path{results/weak_backbone/weak_backbone_summary.csv} and
\path{results/weak_backbone/weak_backbone_agg.csv}.

\paragraph{S7. Qualitative panels.} Additional UMAP rescue panels for immune dendritic cells, Baron pancreas and
stomach are stored under \path{results/umap/}. They are used only as qualitative support for the geometric recall
ceiling and are not used for threshold or model selection.

\paragraph{S8. Provenance audit.} Every publication cache has a manifest and all $76/76$ cached run directories have
complete train/validation/test prediction and latent files. The cached split hashes match the manifest hashes for
$76/76$ runs, so no split/cell-ID provenance mismatch was detected. The git-sha audit is weaker: $64$ caches were
generated on a different commit and $12$ are legacy caches without git-sha recording. Strict final reruns should
therefore use a clean output directory or \texttt{--force}. Audit outputs are in
\path{results/provenance/cache_audit.csv} and \path{results/provenance/cache_audit.md}.

\paragraph{S9. Runtime and memory.} Runtime and peak-memory benchmarking are not yet included in this draft. They
should be added before submission if the target journal requires a computational-cost comparison or if reviewers are
likely to question the post-hoc overhead.
